# Тренировка из GPX

Статический сайт на HTML5, CSS3 и обычном JavaScript ES-модулями. Генерирует синтетические беговые тренировки TCX для тестирования импорта Runkeeper. Без backend, баз данных, авторизации, API-ключей, Node.js, npm и сборки. Leaflet через CDN показывает карту; графики рисуются на Canvas.

## Публикация на GitHub Pages

Загрузите содержимое этой папки в корень публичного репозитория. Сохраните файл `.nojekyll`: он отключает обработку Jekyll. В GitHub выберите **Settings → Pages → Deploy from a branch → main → / (root)** и сохраните. Отдельный workflow или сборка не требуется. После публикации откройте `https://<имя>.github.io/<репозиторий>/`. Локальные пути относительные, сайт работает из подпапки репозитория и через HTTPS.

В папке оставлены только файлы сайта, README, `.gitignore` и `.nojekyll`. Тесты, примеры GPS, HAR, скачанные TCX, архивы и служебные отчёты удалены. `.gitignore` дополнительно исключает GPX/TCX/HAR, архивы, локальные настройки и файлы секретов. Новые файлы перед загрузкой в публичный репозиторий проверяйте отдельно.

Для необязательной локальной проверки нужен статический HTTP-сервер, например `python -m http.server 8080 --bind 127.0.0.1`, затем `http://127.0.0.1:8080/`. Python нужен только для локального сервера. Через `file://` браузеры ограничивают ES-модули и Web Worker.

## Использование

1. Загрузите свой GPX. Появятся маршрут, дистанция и количество точек.
2. Укажите дату, время и пояс: Украина — Киев или Германия — Берлин. Летнее/зимнее время учитываются автоматически; смена пояса сохраняет момент старта. В TCX записывается UTC.
3. Задайте ориентир темпа, отклонение и каденс обеих ног. Каденс используется только для оценки шагов и длины шага на сайте, в TCX не записывается.
4. Пульс при каждом открытии сайта выключен, даже если был включён раньше. При желании раскройте дополнительный пункт и включите его вручную. Явная вставка кода с включённым пульсом восстанавливает этот параметр.
5. Создайте тренировку, проверьте графики и карточки, скачайте TCX. «Новый вариант» меняет случайную часть seed; обычная генерация повторяет результат с теми же настройками и GPX.

## Импорт Runkeeper

Используйте пакетный импорт, проверенный пользователем. [Официальная инструкция](https://help.runkeeper.com/en/hc/bulk-import-gpx-tcx-and-fit-files-to-runkeeper):

1. Откройте Runkeeper.com в Google Chrome и войдите в тот же аккаунт, что в приложении на телефоне. При сомнении сверьте email в настройках приложения.
2. Нажмите **Log**, прокрутите до **Trying to Upload Multiple Files?**, выберите **Get Started**.
3. Выберите скачанный TCX.
4. Дождитесь **Successfully uploaded the following files**, нажмите **Done** и проверьте историю.
5. Откройте приложение на телефоне с интернетом. Тренировка появится после синхронизации этого аккаунта; это может занять некоторое время. Обновите историю или откройте приложение снова.

Дата и время уже содержатся в TCX. Отображение пульса, калорий и шагов зависит от Runkeeper. Перед повторной загрузкой проверьте историю на дубликаты.

## Где взять GPX

В бесплатном [GPX Studio](https://gpx.studio/app): карандаш **Plan or edit a route** → город через **Search** → **Activity → Run/hike**, **Routing** включён → точки A и B, при необходимости промежуточные точки → **File → Export…**. Сохраните GPX и загрузите его на сайт. [Справка построения маршрута](https://gpx.studio/help/toolbar/routing).

## Темп, шаги и пульс

Темп использует тот же принцип, что Android-контроллер RoutePilot: новая равномерно случайная цель внутри заданного диапазона каждые 15–35 секунд; текущий темп приближается к ней экспоненциально с постоянной времени 10 секунд. Seed делает этот процесс повторяемым. Время прохождения GPS-участка вычисляется из аналитического интеграла скорости, а не независимых случайных значений на каждой точке. Средний темп получается из всей длительности и дистанции, не нормализуется к ориентиру и не получает отдельного принудительного смещения. При нулевом отклонении модель постоянная. Например, 6:30 ±30 задаёт локальные границы 6:00–7:00.

Каденс умеренно реагирует на скорость с дополнительным сглаживанием и небольшой независимой вариацией. Оставшаяся часть изменения скорости приходится на длину шага. Скорость = 1000 / темп (с/км), длина шага = скорость × 60 / каденс. Шаги интегрируются по времени. Каденс нужен для этих расчётов, но поля Cadence, RunCadence, AvgRunCadence, MaxRunCadence и атрибут CadenceSensor в TCX отсутствуют.

Для измерения каденса пробегите несколько минут в привычном темпе, за 30 секунд посчитайте касания одной ногой и умножьте на 4. Например, 42 касания = 168 шагов/мин обеими ногами. Повторите 2–3 раза. Пример 170 ±5 не является универсальной целью для настоящего бега.

Необязательный пульс имеет разогрев, подъёмы/снижения и сглаженную реакцию на скорость с задержкой около 25 секунд. Заданный пульс — ориентир; seed меняет фактическое временное среднее до ±40% выбранного отклонения. Локальные значения сохраняются в выбранном диапазоне. Пример 145 ±12 — только параметры синтетических данных, не рекомендация зоны нагрузки. При выключении пульса ни точки, ни его итоговые поля в TCX не записываются.

Калории автоматически оцениваются как дистанция (км) × 70 кг × 1 ккал/(кг·км), с округлением. Фиксированная масса 70 кг позволяет обходиться без отдельного поля; это условная оценка, не личный расход энергии. [Исследовательская модель стоимости бега](https://arxiv.org/abs/q-bio/0609007). Индивидуальная экономичность и рельеф не учитываются.

## Экспорт и ограничения

GPX поддерживает trk/trkseg/trkpt, rte/rtept, namespace и высоты. Дистанция — Haversine, интерполяция — сферическая. Разрывы не соединяются; избыточные одинаковые точки и сегменты без движения исключаются из модели.

Основной экспорт использует GPS каждую целую секунду. Сначала длительность каждого трека приводится к ближайшей секунде, затем пересчитываются координаты, дистанция, скорость и интегралы пульса/каденса/шагов. Это уменьшило наблюдавшееся искажение финишного темпа при импорте. Карточки и графики показывают данные этого же файла. Начало, конец и накопленная дистанция трека сохраняются. На резком повороте секундная интерполяция может срезать угол и создать отдельное GPS-замедление; исходная карта остаётся неизменной.

Если сегмент короче секунды или округление заметно выводит темп за границы, автоматически сохраняются точные временные метки, без запрета скачивания. Очень длинные тренировки используют более редкий целочисленный шаг для защиты памяти. Раздельные треки получают одну секунду между ними без расстояния и шагов. Округление может менять итоговое среднее; строка перед скачиванием показывает изменение времени.

Ресурсные пределы: 32 МБ GPX, 200 000 исходных и 350 000 модельных/экспортных точек; маршрут от 1 метра. Слишком длительный профиль ограничен по числу смен цели для защиты браузера. XML проверяется DOMParser и семантическими проверками, DTD/ENTITY запрещены. Браузер не выполняет XSD-валидацию. Перед очисткой проверочный TCX прошёл обе официальные схемы Garmin.

TCX v2 содержит Running, Lap, отдельные Track, UTC-время, координаты, высоту при наличии, расстояние, ActivityExtension v2 Speed/AvgSpeed, Calories и расчётные Steps. При включённом пульсе — HeartRateBpm и средний/максимальный пульс. Каденс в файл не передаётся. Notes обозначает синтетические данные, условную массу для калорий, оценку шагов и seed. Формат ограничивает Calories/Steps числом 65 535: Calories ограничивается, Steps при превышении опускается; полные оценки остаются в Notes.

## Seed и сохранение настроек

Код RUN2 содержит UTC-старт, пояс, темп, отклонения, внутренний каденс, параметры пульса и случайное значение. Вставка восстанавливает настройки. Для повторения нужны тот же GPX и та же версия модели. Старые RUN1 принимаются с выключенным пульсом и поясом Украины; после изменения алгоритма старый seed не обязан повторять профиль прошлой версии.

В localStorage сохраняются только настройки и тема, GPX не сохраняется. При обычном открытии страницы переключатель пульса всегда выключен. Несуществующее весеннее время отклоняется; повторяющееся осеннее время при ручном вводе выбирает первое вхождение, сохранённый UTC из кода сохраняет точный момент.

## Файлы

| Файл | Назначение |
| --- | --- |
| index.html / style.css | Интерфейс и адаптивный дизайн |
| app.js | Форма, File API, карта, Canvas, настройки |
| gpx.js | GPX, Haversine, геометрия |
| simulation.js / simulation-worker.js | Темп, шаги, пульс и калории; расчёт в Worker |
| export-profile.js | Секундный экспорт и согласованные итоги |

Файлы обрабатываются локально. Leaflet CDN и OpenStreetMap требуют интернет; запросы карты содержат область просмотра. При недоступной карте генерация остаётся доступной. Синтетические данные предназначены для тестирования, не подтверждение настоящих пробежек или соревнований.
